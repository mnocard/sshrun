# sshrun — пошаговое выполнение команд на нескольких серверах по SSH

## Сборка

```
go mod tidy
go build -o sshrun.exe .          # Windows
GOOS=windows go build -o sshrun.exe .   # кросс-сборка с Linux/macOS
```

Запуск: `sshrun.exe [-c config.json]`.

Если `-c` не указан (и нет позиционного аргумента с путём), программа ищет рядом
с собой (в каталоге, где лежит сам .exe) файлы, чьё имя заканчивается на
`config.json` без учёта регистра — подходят `config.json`, `dev-config.json`,
`testconfig.json`, `123_Config.JSON` и т.п.:
- ни одного не найдено — как раньше, config.json в текущем каталоге;
- найден один — используется автоматически (это будет написано в консоли);
- найдено несколько — программа покажет список и попросит выбрать номер или
  ввести точное имя файла.

`-c путь` или просто `sshrun.exe путь/к/файлу.json` всегда используется как есть,
без automatического поиска — это для автозапуска по расписанию/из скриптов.

## Конфиг

Формат — как в вашем примере. Дополнительно поддерживается:

| Поле | Значение |
|---|---|
| `servers[].key_file`, `key_passphrase` | вход по приватному ключу (вместо/вместе с `password`) |
| `workflow[].servers[].commands` | массив команд (можно вместе с `command`) |
| `replace.regex` | `true` — `find` это регулярное выражение |
| `settings.log_file` | по умолчанию `sshrun.log` |

Внутри одной записи порядок такой: `command(s)` → `upload` → `replace`.
Несколько записей с одним сервером в шаге выполняются на нём последовательно;
разные серверы — параллельно. Запись с пустой `command` просто подключает сервер.

Настройки:
- `pause_on_enter` (по умолчанию `true`) — после каждого шага ждать пустую строку.
  При `false` шаги идут подряд; остановка происходит только при ошибке.
- `press_any_key_before_next_step` — то же ожидание (ввод построчный, без «любой клавиши»).
- `default_sudo` — пароль из конфига автоматически подставляется в запрос `sudo`;
  загрузка/правка файлов, на которые у пользователя нет прав, идёт через `sudo`
  (временный файл в `/tmp` + `sudo cp` / `sudo sh -c 'cat > файл'`).
- `connect_timeout` — секунды.

## Команды в диалоге (после шага)

| Ввод | Действие |
|---|---|
| Enter | выполнить следующий шаг |
| `<сервер> <команда>` | выполнить команду на сервере (`dev,dev-lk <команда>` — на нескольких) |
| `all <команда>` | на всех серверах |
| `upload <сервер\|all> <локальный> <удалённый>` | загрузить файл/каталог (пути с пробелами — в кавычках) |
| `edit <сервер> <файл>` | скачать → открыть в редакторе → отправить обратно |
| `repeat [N]` | повторить шаг N (по умолчанию — последний / упавший) |
| `retry` | после ошибки продолжить шаг с места остановки |
| `skip` | после ошибки: игнорировать и идти дальше |
| `goto N` | перейти к шагу N и выполнить его |
| `steps`, `status`, `help`, `quit` | служебные |
| `break <сервер>` | Ctrl+C команде на сервере |

Пока команда выполняется, строка `<сервер> <текст>` уходит ей на stdin
(ответ на `[y/N]` и т.п.); если занят один сервер — можно вводить просто `y`.

Загрузка идёт по правилам `scp`: если удалённый путь — существующий каталог или
заканчивается на `/`, файл/каталог кладётся внутрь под своим именем.

Редактор: `SSHRUN_EDITOR` → `VISUAL` → `EDITOR` → `notepad` (Windows) / `nano`, `vim`, `vi`.

## Как определяется «команда выполнена» и «ошибка»

На каждом сервере открыта постоянная оболочка (bash на PTY): `cd`, переменные и т.п.
сохраняются между командами. После каждой команды в тот же поток отправляется
служебный маркер с кодом возврата; пока оболочка не вернула ввод, команда считается
выполняющейся. **Ошибка** — ненулевой код возврата, сбой SFTP/замены/подключения
или обрыв соединения. При ошибке новые действия не запускаются ни на одном сервере
(уже идущие команды дожидаются завершения), шаг блокируется, пока вы не сделаете
`retry` / `repeat` / `skip`. Пустая строка при активной ошибке шаг не продолжает.

## Лог

Всё пишется в `log_file` с меткой времени: вывод серверов (`OUT`), команды (`CMD`),
ввод пользователя (`IN`), события (`SYS`), ошибки (`ERR`). Пароли в лог не попадают.

## Ограничения

- Не запускайте в шаге интерактивные вложенные оболочки (`sudo -i`, `su -`, `bash`):
  команда завершится только при выходе из них. Используйте `sudo <команда>`.
- Отпечаток ключа сервера не проверяется (`InsecureIgnoreHostKey` в `conn.go`).
- Для загрузки/правки файлов на сервере должен быть включён SFTP-субсистем.
- Пароли хранятся в конфиге открытым текстом — ограничьте права на файл.
