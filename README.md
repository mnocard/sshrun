# sshrun — пошаговое выполнение команд на нескольких серверах по SSH

Программа подключается по SSH к нескольким серверам сразу, выполняет заранее
описанный в JSON-конфиге сценарий (шаг за шагом, с паузами и обработкой ошибок),
даёт загружать файлы и править текстовые файлы на серверах. Всё, что происходит,
одновременно видно на экране и пишется в лог-файл.

У программы два режима — графический (по умолчанию) и консольный (`-cli`).
Оба работают с одним и тем же конфигом и одинаково выполняют сценарий;
разница только в том, как вы это видите и чем управляете.

## Сборка

```
go mod tidy
go build -o sshrun.exe .                # сборка под текущую ОС
GOOS=windows GOARCH=amd64 go build -o sshrun.exe .   # кросс-сборка под Windows
GOOS=darwin  GOARCH=amd64 go build -o sshrun-mac .   # кросс-сборка под macOS
```

Один исполняемый файл, без установки и без внешних зависимостей — веб-интерфейс
вшит внутрь (`go:embed`), браузером пользуется уже установленный в системе.

## Запуск

```
sshrun.exe                       — графический режим, выбор конфига в окне
sshrun.exe -c config.json        — графический режим, конфиг сразу известен
sshrun.exe -cli -c config.json   — консольный режим (как раньше)
```

Флаги:

| Флаг | Значение |
|---|---|
| `-c путь` | конфиг сразу известен — окно/консоль выбора не показываются |
| `-cli` | консольный режим без браузера |
| `-port N` | порт локального веб-сервера (по умолчанию — случайный свободный) |
| `-no-browser` | не открывать окно браузера автоматически, только вывести адрес в консоль |

## Графический режим

При запуске без `-c` программа ищет рядом с собой (в каталоге, где лежит сам
.exe, и в текущей папке) файлы `*config.json` без учёта регистра — подходят
`config.json`, `dev-config.json`, `testconfig.json`, `123_Config.JSON` и т. п.
Один найден — открывается сразу, несколько — показывается список на выбор
в самом окне, ни одного — можно указать путь вручную.

Программа поднимает веб-сервер на `127.0.0.1` (наружу, за пределы вашего
компьютера, не смотрит) и открывает окно без адресной строки — Edge или Chrome
в режиме приложения; если ни того ни другого нет, открывается обычный браузер.
Адрес с ключом доступа также печатается в консоли — по нему это же окно можно
открыть заново (в т. ч. если случайно закрыли), работа на серверах при этом
не прерывается: программа выполняет сценарий сама по себе, окно — просто
способ на это посмотреть и чем-то управлять.

**После последнего шага программа не завершается** — можно повторить любой шаг
(`repeat`), перейти к другому (`goto`), выполнить произвольную команду; выйти —
кнопкой «Выход» в окне (или дважды Ctrl+C в консоли, где программа запущена).

В окне: слева — список серверов (адрес, подключён/занят/чем именно, кнопка
прервать текущую команду Ctrl+C) и список шагов (статус, для каждого сервера —
прогресс и текст ошибки, если была); справа — живой лог со строкой ввода внизу.
Кнопка со стрелкой рядом с сервером в списке открывает встроенный редактор
файла на нём. Кнопка «⬇ лог» скачивает полный лог-файл текущей сессии.

### Про безопасность локального веб-интерфейса

Доступ защищён ключом в адресе (виден только в консоли и после открытия
окна — в cookie браузера) и проверкой, что запрос пришёл с этого же
компьютера. Расчёт на то, что программой пользуется тот, кто её запустил,
на своей же машине — это не публичный сервис. **Не пробрасывайте порт
наружу «как есть»** (в интернет или в общую сеть без разбора) — у него нет
шифрования, и у любого, кто получит адрес с ключом, будет полный доступ
к тому, что доступно и вам: выполнение команд и чтение/запись файлов на
всех серверах из конфига.

Если нужен доступ с другого компьютера — самый простой и безопасный способ
сейчас есть уже без единой правки: SSH-туннель до машины, где запущена
программа —
```
ssh -L 8080:127.0.0.1:ПОРТ_ПРОГРАММЫ пользователь@машина-с-программой
```
и открыть `http://127.0.0.1:8080/...` у себя (адрес с ключом программа
печатает в консоли на той машине). Полноценный доступ по IP для нескольких
людей — отдельная задача (TLS, нормальная аутентификация вместо ключа
в адресе, разграничение прав), в текущей версии её нет.

## Консольный режим

Запускается флагом `-cli`, ведёт себя как в первых версиях программы —
весь диалог в терминале. Подробности ниже относятся к обоим режимам
(графический просто рисует то же самое в окне вместо текста).

## Конфиг

```json
{
  "servers": [
    {"name": "dev", "host": "10.0.0.5", "port": 22, "username": "user", "password": "***", "color": "#4d8dff"}
  ],
  "settings": {"log_file": "run.log", "connect_timeout": 30, "default_sudo": true, "pause_on_enter": true},
  "highlight": {"rules": [{"pattern": "МОЯ_МЕТКА", "color": "#ff00ff", "bold": true}]},
  "gui": {"font_size": 14, "max_lines": 20000, "timestamps": true},
  "workflow": [
    {"step_name": "Шаг", "step_description": "Описание", "servers": [
      {"server": "dev", "command": "echo hi"}
    ]}
  ]
}
```

### servers[]

| Поле | Значение |
|---|---|
| `name`, `host`, `port`, `username`, `password` | как и раньше; `port` по умолчанию 22 |
| `key_file`, `key_passphrase` | вход по приватному ключу вместо/вместе с паролем |
| `color` | цвет метки сервера в графическом режиме (CSS-цвет, например `"#4d8dff"`); не задан — цвет выбирается автоматически по имени |

### workflow[].servers[] (одна запись = одно или несколько действий на сервере)

| Поле | Значение |
|---|---|
| `command` | одна команда |
| `commands` | массив команд — выполняются по очереди (можно вместе с `command`) |
| `upload` | `{"local": "...", "remote": "..."}` — файл или каталог, правила как у `scp` |
| `replace` | `{"file": "...", "find": "...", "replace": "...", "regex": false}` — замена текста в файле на сервере |

Порядок внутри одной записи: `command`/`commands` → `upload` → `replace`.
Несколько записей с одним сервером в шаге выполняются на нём по очереди;
разные серверы в шаге — параллельно. Пустая `command` просто подключает сервер.

### settings

| Поле | Значение |
|---|---|
| `log_file` | по умолчанию `sshrun.log` |
| `connect_timeout` | секунды, по умолчанию 30 |
| `default_sudo` | пароль из конфига подставляется в запрос sudo; загрузка/правка файлов без прав идёт через sudo (временный файл + `sudo cp` / `sudo sh -c cat`) |
| `pause_on_enter` | по умолчанию `true` — ждать пустую строку после каждого шага; `false` — шаги идут подряд, остановка только при ошибке |
| `press_any_key_before_next_step` | то же самое (ввод построчный, не посимвольный) |

### highlight — подсветка вывода (тот самый настраиваемый пункт)

Без этого раздела в конфиге действуют встроенные правила: слова вида
`error/fail/timeout/denied` и «ошибка/не удалось/отказано» — красным жирным,
`warning/deprecated` — жёлтым, `success/done/completed` и «успешно/готово» —
зелёным, статусы docker вроде `unhealthy`/`Exited (1)` — оранжевым.

```json
"highlight": {
  "enabled": true,
  "include_defaults": false,
  "rules": [
    {"pattern": "DEPLOY_OK", "color": "#5fd38d", "bold": true},
    {"pattern": "^\\[FATAL\\]", "regex": true, "background": "#4a1020", "scope": "line", "kinds": ["out"]}
  ]
}
```

| Поле правила | Значение |
|---|---|
| `pattern` | подстрока, или регулярное выражение JavaScript при `regex: true` |
| `ignore_case` | по умолчанию `true` |
| `color`, `background`, `bold`, `italic`, `underline` | оформление; нужно хотя бы одно |
| `scope` | `"match"` (по умолчанию, красится только найденное) или `"line"` (вся строка) |
| `kinds` | какие строки затрагивает: `out` (вывод сервера), `err`, `warn` (отклонённая команда/неверный ввод), `sys`, `info`, `cmd`, `in`; по умолчанию — все |

`enabled: false` — подсветка выключена совсем. Свои `rules` заменяют встроенные;
`include_defaults: true` — добавить встроенные вслед за своими. Подсветка —
только для графического режима, на лог-файл и консольный режим не влияет.

### gui

| Поле | Значение |
|---|---|
| `font_size` | размер шрифта лога в px, 9–32, по умолчанию 13 |
| `max_lines` | сколько строк держать в окне, по умолчанию 20000 (лог-файл при этом полный, без обрезки) |
| `timestamps` | показывать время у строк, по умолчанию `true` |

## Команды в диалоге (после шага, в консоли или в строке ввода окна)

| Ввод | Действие |
|---|---|
| Enter (пустая строка) | выполнить следующий шаг / продолжить после паузы |
| `<сервер> <команда>` | выполнить команду на сервере (`dev,dev-lk <команда>` — на нескольких) |
| `all <команда>` | на всех серверах |
| `upload <сервер\|all> <локальный> <удалённый>` | загрузить файл/каталог (пути с пробелами — в кавычках) |
| `edit <сервер> <файл>` | открыть файл во встроенном редакторе (в CLI — скачать/открыть во внешнем/отправить) |
| `repeat [N]` | повторить шаг N (по умолчанию — последний/упавший) |
| `retry` | после ошибки — продолжить шаг с места остановки |
| `skip` | после ошибки — игнорировать и идти дальше |
| `goto N` | перейти к шагу N и выполнить его |
| `break <сервер>` / `break сервер1,сервер2` / `break all` | Ctrl+C команде на сервере(ах); в графическом режиме — кнопки ⏹ рядом с «Продолжить», пока хоть один сервер занят |
| `status` / `servers` | список серверов и их адресов |
| `steps`, `help`, `quit` | список шагов, справка, выход |

Пока команда выполняется, строка `<сервер> <текст>` уходит ей на stdin
(ответ на `[y/N]` и т. п.); если занят ровно один сервер, можно вводить
просто ответ без имени сервера.

## Как определяется «команда выполнена» и «ошибка»

На каждом сервере открыта постоянная оболочка (bash на PTY) — `cd`, переменные
и т. п. сохраняются между командами. После каждой команды в тот же поток
отправляется служебный маркер с кодом возврата; пока оболочка не вернула
ввод — команда считается выполняющейся. Соединение поддерживается активно
(keepalive и обнаружение обрыва) — рассчитано и на команды, идущие 20+ минут.

**Ошибка** — ненулевой код возврата, сбой SFTP/замены/подключения или обрыв
связи. При ошибке новые действия не запускаются ни на одном сервере (уже
идущие — дожидаются завершения), шаг блокируется до `retry` / `repeat` / `skip`.

## Загрузка файлов

Идёт параллельными SFTP-пакетами (а не по одному с ожиданием подтверждения
каждого) — на сети с заметной задержкой это в десятки раз быстрее. Для файлов
от 8 МБ раз в 2 секунды показывается прогресс (%, объём, скорость) — сам подсчёт
не замедляет передачу. Правила путей — как у `scp`: если удалённый путь —
существующий каталог или заканчивается на `/`, файл/каталог кладётся внутрь
под своим именем.

Пока файл или каталог грузится, сервер считается занятым (в графическом режиме —
кнопка «Остановить», в любом — `break <сервер>`) ровно так же, как при
выполнении команды. Остановка — настоящая: текущий файл обрывается на том месте,
где был в момент нажатия, новые файлы каталога не начинаются, шаг помечается
ошибкой «загрузка отменена пользователем» — дальше решаете сами (`retry`/`repeat`/`skip`).

## Лог

Всё пишется в `log_file` с меткой времени: вывод серверов (`OUT`), команды
(`CMD`), ввод пользователя (`IN`), события (`SYS`), ошибки (`ERR`). Пароли
в лог не попадают. В графическом режиме лог можно скачать кнопкой в окне.

## Ограничения

- Не запускайте в шаге `sudo -i`, `su -`, `bash` без выхода — такая команда
  завершится только при выходе из вложенной оболочки; пишите `sudo <команда>`.
- Отпечаток ключа сервера не проверяется (`InsecureIgnoreHostKey` в `conn.go`).
- Для загрузки/правки файлов на сервере нужен включённый SFTP-субсистем.
- Пароли в конфиге хранятся открытым текстом — ограничьте права на файл.
- Встроенный редактор работает с текстом в UTF-8 до 5 МБ; для остального —
  `replace` в конфиге или внешний редактор через SFTP-клиент.
